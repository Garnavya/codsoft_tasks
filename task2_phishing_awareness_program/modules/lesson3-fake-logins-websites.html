Lesson 03

Fake Login Pages & Fraudulent Websites

Threat actors routinely clone legitimate authentication interfaces to harvest user credentials and two-factor session tokens. Learn how URL structures work and why the green padlock icon does not guarantee safety.

Anatomy of a Fraudulent URL

Attackers craft deceptive subdomains to mislead users who only scan the initial characters of a web address. Let us dissect how browser URL routing really functions:

https://login.secure-bank.com.attacker-portal.net/auth/signin?session=xyz
1. Scheme (https://)

Indicates TLS encryption in transit. Crucially, encryption does not equal safety!

2. Subdomain Prefix

"login.secure-bank.com" is merely an arbitrary subdomain label controlled by the attacker.

3. Apex Domain (The Real Host)

attacker-portal.net is the actual destination server receiving your data.

4. Path & Query

Routes the request to the attacker's harvesting script on their server.

⚠️ The Dangerous Misconception: "The Padlock Means It's Safe"

For decades, users were advised: "Look for the padlock icon before entering credentials." Today, this advice is obsolete and dangerous.

  • What HTTPS actually means: The data traveling between your browser and the remote server is encrypted against local network eavesdroppers (e.g., someone on coffee shop Wi-Fi).
  • What HTTPS does NOT mean: It provides zero warranty regarding who owns the server or whether that server is honest. Over 80% of phishing websites now deploy valid SSL/TLS certificates issued free of charge by automated providers (such as Let's Encrypt or Cloudflare).
  • Takeaway: An encrypted connection to a cybercriminal is still an encrypted transmission directly into an attacker's database!
